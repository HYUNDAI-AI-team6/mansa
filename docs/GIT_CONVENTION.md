# Git 협업 컨벤션

팀 프로젝트의 커밋, 브랜치, 이슈, Pull Request(PR) 작성 규칙을 정의합니다.

## 1. Commit Convention

커밋 메시지는 `type: 작업 내용` 형식을 따릅니다.

**예시:** `feat: 로그인 API 구현`

| 타입 | 설명 |
| --- | --- |
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `hotfix` | 운영 환경의 긴급 버그 수정 |
| `design` | CSS 등 사용자 UI 디자인 변경 |
| `style` | 코드 포맷 변경 등 기능 변경이 없는 경우 |
| `refactor` | 기능 변경 없는 코드 리팩토링 |
| `perf` | 성능 개선 및 최적화 |
| `comment` | 필요한 주석 추가 및 변경 |
| `docs` | README.md와 같은 문서 작성 및 수정 |
| `test` | 테스트 코드 추가 및 수정 (프로덕션 코드 수정 없음) |
| `build` | 빌드 시스템 및 의존성 변경 (예: uv, pip, Gradle, Maven) |
| `ci` | CI/CD 설정 및 스크립트 변경 (예: GitHub Actions) |
| `rename` | 파일 및 폴더명 변경 |
| `remove` | 파일 및 폴더 삭제 |
| `chore` | 기타 유지보수 및 설정 작업 |
| `revert` | 이전 커밋 되돌리기 |

### 커밋 메시지 작성 규칙

- 커밋 메시지는 한국어로 작성합니다.
- 제목 끝에 마침표를 사용하지 않습니다.
- 하나의 커밋에는 하나의 논리적 작업만 포함합니다.
- 작업 내용을 명확하고 간결하게 작성합니다.
- 필요한 경우 본문에 상세 변경 사항을 작성합니다.

## 2. Branch Convention

브랜치 이름은 `type/이슈번호-작업내용` 형식을 따릅니다.

**예시:** `feat/17-login-api`

- 브랜치 이름은 영어 소문자를 사용합니다.
- 단어는 하이픈(`-`)으로 구분합니다.
- 이슈 번호를 반드시 포함합니다.
- 하나의 이슈에 하나의 작업 브랜치를 생성하는 것을 원칙으로 합니다.
- PR이 머지되면 작업 브랜치를 삭제합니다.

**브랜치 이름 예시**

```text
feat/17-login-api
feat/18-signup-api
fix/21-token-error
refactor/25-auth-service
docs/30-readme-update
```

## 3. Issue Convention

이슈 제목은 `[type] 작업 내용` 형식을 따릅니다.

**예시:** `[feat] 로그인 API 구현`

**이슈 제목 예시**

- `[feat] 회원가입 API 구현`
- `[fix] JWT 토큰 만료 오류 수정`
- `[refactor] 사용자 인증 서비스 개선`
- `[docs] README 작성`

### 이슈 본문 템플릿

GitHub 이슈 작성 시 `.github/ISSUE_TEMPLATE/feature.md` 템플릿을 사용합니다.

```markdown
## 💡 Issue: 이슈 요약
구현할 기능이나 작업의 목적을 작성해 주세요.

## 📝 Todo: 할 작업
- [ ] 작업 내용 입력
- [ ] 작업 내용 입력
- [ ] 작업 내용 입력

## 🤖 AI 활용 여부
- [ ] AI 활용
- [ ] AI 미활용

**AI 활용 내용:**
<!-- 사용한 AI 도구와 활용 범위를 작성해 주세요. -->
```

> 이슈 템플릿의 기본 제목은 `[feat]`이며, 실제 작업 유형에 따라 `[fix]`, `[docs]` 등으로 변경합니다.

## 4. Pull Request Convention

PR 제목은 `[type] 작업 내용 (#이슈번호)` 형식을 따릅니다.

**예시:** `[feat] 로그인 API 구현 (#17)`

**PR 제목 예시**

- `[feat] 회원가입 API 구현 (#18)`
- `[fix] JWT 토큰 만료 오류 수정 (#21)`
- `[refactor] 사용자 인증 로직 개선 (#25)`
- `[docs] README 실행 방법 추가 (#30)`

### PR 본문 템플릿

GitHub PR 작성 시 `.github/pull_request_template.md` 템플릿을 사용합니다.

```markdown
## 🔗 연결된 이슈
<!-- 관련된 이슈 번호를 작성해 주세요. -->
- Closes #

## 📝 작업 내용
<!-- 이번 PR에서 구현하거나 수정한 내용을 작성해 주세요. -->
-
-
-

## 🧪 테스트 결과 및 테스트 방법
<!-- 테스트 방법과 실행 결과를 작성해 주세요. -->

### 테스트 방법
1.
2.
3.

### 테스트 결과
- [ ] 정상 동작 확인
- [ ] 예외 상황 확인
- [ ] 기존 기능 영향 확인

**추가 설명:**

## 📸 스크린샷
<!-- UI 변경이나 실행 결과를 확인할 수 있는 이미지를 첨부해 주세요. -->

| 변경 전 | 변경 후 |
| --- | --- |
| 이미지 첨부 | 이미지 첨부 |

## 📚 레퍼런스
<!-- 구현 시 참고한 문서, 공식 문서, 기술 자료 등의 링크를 첨부해 주세요. -->
-
-
```

### PR 작성 규칙

- PR 제목에 관련 이슈 번호를 포함합니다.
- PR 본문에 주요 변경 사항을 작성합니다.
- 테스트 방법과 수행 결과를 기재하고 해당 체크리스트를 표시합니다.
- UI 변경 사항이 있는 경우 변경 전·후 스크린샷을 첨부합니다.
- PR 본문에 `Closes #이슈번호`를 작성하여 이슈를 연결합니다.
- PR이 기본 브랜치에 머지되면 연결된 이슈가 자동 종료되도록 설정합니다. (GitHub의 종료 키워드는 기본 브랜치에 머지될 때 작동합니다.)

## 5. GitHub 템플릿 파일 위치

```text
프로젝트 루트/
├── GIT_CONVENTION.md
└── .github/
    ├── ISSUE_TEMPLATE/
    │   └── feature.md
    └── pull_request_template.md
```

위 파일을 GitHub 저장소에 커밋하면 이슈 및 PR 작성 화면에서 템플릿을 활용할 수 있습니다.
